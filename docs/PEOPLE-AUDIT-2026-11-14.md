   последняя явка 25.06, последний график 21.06. **[проверено]**
2. **Почему — цепочка блокеров** **[проверено]**:
   - «Я здесь» требует опубликованную смену в графике на сегодня. Графика нет → кнопки нет.
   - В SO геоявка включена (`attendance_enabled=true`), но адрес/координаты не заданы. Веб показывает
     «гео не настроено», явку отметить нельзя вообще.

   Итог: модуль спроектирован как цепочка «график → явка → чек-лист», и первое звено никто не делает.

## 1. Критично (безопасность, потеря данных)

**К1. Фильтр с неизвестной операцией молча выбрасывается → update/delete по всему ресторану.** **[проверено]**
`app/api/db/route.ts:393-399` (`applyFilters` пропускает op не из `FILTER_OPS`), проверка на
`:569, :585` смотрит только на `filters.length`. Запрос `{op:'delete', table:'shift_checklist_completions',
filters:[{op:'x', col:'id', val:1}]}` проходит «фильтр обязателен» и удаляет **все** строки таблицы
ресторана. То же для update. Работает для любой таблицы, куда у сотрудника есть запись по POLICY.
Фикс: отклонять запрос (400), если хоть один фильтр невалиден (уже есть `validBookingFilter` — применить ко всем).

**К2. `shift_checklist_completions` пишет любой сотрудник с People без проверок.** **[проверено]**
`route.ts:65` (write: people), таблица не в `PEOPLE_GUARDED` (`route.ts:217`) и не разбирается в
`applyPeoplePolicy`. Сотрудник через шлюз может удалить/переписать любой прогон чек-листа или аудита
(включая менеджерскую верификацию), минуя CAS-эндпоинт `/api/people/checklist-item`.
Фикс: писать только через `/api/people/checklist-item` и менеджерские операции; для не-официальных — запрет.

**К3. Сотрудник может подделать свою явку.** **[проверено]**
`lib/peoplePolicy.ts:162-172`: на insert/upsert `attendance_records` подменяется только `staff_id`,
остальные поля (время прихода, статус, опоздание, координаты) — как прислал клиент. Через шлюз
можно записать «пришёл вовремя» задним числом или из дома. Влияет на Дисциплину.
Фикс: время/статус/опоздание считать на сервере (как сделано для ЗП).

**К4. Офлайн-очередь чек-листа на iOS теряет отметки.** **[проверено]**
`PeopleModel.swift:881-901`: досылка читает очередь, по одной шлёт в сеть, потом перезаписывает
очередь остатком. Отметки, поставленные во время досылки, затираются.

## 2. Серьёзные ошибки

**В1. iOS: после утверждения обмена статус «откатывается».** **[проверено]**
`PeopleModel.swift:592-602` → `loadSwaps()` читает `shift_swap_requests` из 5-минутного кэша
(`DB.swift:195`, без `.fresh()`), а `API.people` кэш не сбрасывает. Менеджер видит «ожидает»,
жмёт «Утвердить» ещё раз → 409 → «не удалось сохранить».

**В2. iOS: правка аудита не сохраняет название, охват и исполнителя.** **[проверено]**
`PeopleModel.swift:918-923`: update пишет только items/role/recurrence; `title`, `target_scope`,
`assigned_staff_id` теряются, хотя форма их даёт менять.

**В3. iOS: «Сообщить о проблеме» закрывается даже при ошибке.** **[проверено]**
`PeopleChecklists.swift:791-793` игнорирует результат `createTask` и вызывает `dismiss()` —
комментарий, исполнитель и фото пропадают.

**В4. Правка опубликованной смены прячет её от сотрудника.** **[проверено]**
`components/people/ScheduleTab.tsx:44-47` всегда шлёт `published:false`. Менеджер поправил время
уже опубликованной смены → она стала черновиком, пропала у сотрудника, «Я здесь» исчез.

**В5. Ночная смена после полуночи ломает чек-лист закрытия (веб и iOS).**
Всё ищется по календарному «сегодня» устройства: прогоны чек-листа (`audits.tsx:352`), открытая
смена (`audits.tsx:1091`, `PeopleModel.swift:614`), явка (`audits.tsx:1088`), график (`tabs-shifts.tsx:303, 468`),
менеджерский список явки (`PeopleShiftsHub.swift:211-224`). Смена 18:00–02:00: в 00:30 чек-лист
закрытия пустой, «сначала откройте смену», требует новую явку. Фикс прошлой волны покрыл только
закрытие самой явки.

**В6. Геогейт открыт при сбое загрузки настроек (iOS).**
`PeopleModel.swift:400-403, 453`: если `restaurant_settings` не загрузились, `checkIn` пропускает
проверку расстояния, а чек-лист — наоборот закрыт. Логика расходится.

**В7. Ошибка сети прячет кнопку «Я здесь» (iOS).**
`PeopleModel.swift:418-419`: `try?` на графике дня → nil → «нет смены сегодня», хотя смена есть.

**В8. История ЗП-окладов пишется без проверки ошибок.**
`app/dashboard/(shell)/team/page.tsx:91-102`: если запись в `salary_history` не прошла, оклад
меняется, а история — нет → прошлые месяцы снова пересчитываются по новому окладу (тот самый баг,
ради которого делали `salary_history`). Таблица в проде пока пуста.

## 3. Средние

Сервер / права
- Сотрудник читает явку всех (включая координаты прихода), все заявки, текст всех задач, все обмены —
  фильтр только в интерфейсе (`lib/peoplePolicy.ts:118, 145`).
- `/api/people/checklist-item`: `photo_url` — любая строка до 1000 символов (открывается менеджером
  как ссылка/картинка); `completion_id` не сверяется с `checklist_id`; на аудит, назначенный другому,
  можно ставить отметки (`route.ts:21-28, 73-79`).
- `/api/people/checklist-item:106`: `staff_id` прогона перезаписывается последним, кто отметил пункт →
  рейтинг и статистика приписывают работу не тому.
- Дата по умолчанию в `checklist-item` — UTC (`route.ts:77, 88`). Сейчас клиенты шлют дату, но это мина.
- Обмен сменой: нет защиты от двойной заявки и от того, что коллега уже работает в этот день
  (`peoplePolicy.ts:195-209`, `tabs-shifts.tsx:117-132`). Отклонение менеджером без проверки статуса —
  гонка с утверждением (`tabs-shifts.tsx:155-161`).

Смены / явка
- Веб: уход нельзя отметить без геопозиции и без сообщения (`tabs-shifts.tsx:386-392`).
- Опоздание считается по часовому поясу устройства, не заведения (`tabs-shifts.tsx:357-363`).
- iOS: график месяца без защиты от гонки при быстром листании (`PeopleModel.swift:344-357`).
- iOS: двойной тап «Запустить аудит» / «Завершить восьмёрку» → два прогона и два пуша
  (`PeopleModel.swift:763-773, 973-987`). На вебе то же для закупки (`tabs-ops.tsx:361`), задач, обменов.

Задачи / заявки / закуп
- Списки берут последние 100–200 строк ресторана и потом фильтруют «мои» → у сотрудника пропадают
  свои старые заявки/обмены (`PeopleModel.swift:230`, `tabs-tasks.tsx:62-64, 138`, `tabs-shifts.tsx:101`).
- iOS: задача «на роль» при частичной ошибке пишет «создано N» (`PeopleModel.swift:179-196`).
- Дедуп нарушений по названию пункта на 7 дней по всему ресторану — новое нарушение на другой смене
  не создаёт задачу (`audits.tsx:117-122`, `PeopleModel.swift:154-156`).
- iOS: «Отмена» в заказе отменяет без подтверждения (`PeopleZalPurchase.swift:380`); «Отмена» в
  восьмёрке выбрасывает весь обход без подтверждения (`PeopleWalk.swift:130`).

Команда (дашборд владельца)
- Создание сотрудника не атомарно: `employees` создан, `staff` упал → повтор создаёт второго
  (`team/page.tsx:145-161`).
- Поиск доступа по имени при пустом `employee_id` — у тёзок правка одного меняет другого
  (`team/page.tsx:83-84, 174`). В SO 4 из 9 без связи.
- Колонка «карта» в Команде (`employees.card_amount`) и «на карту» в личной ЗП
  (`monthly_card_amounts`) — разные источники, могут не совпадать.
- Настройки уведомлений: вечный спиннер при ошибке, дубли строк при быстром переключении
  (`tabs-salary.tsx:238-249`).

Выход
- Веб: «Выйти» не стирает локальную личность `mise_staff_<rid>` — следующий на этом устройстве
  видит интерфейс предыдущего (`PeopleApp.tsx:121`). Проверить.

## 5. UX и структура — что перегружено

**Карта сейчас**
- Сотрудник: 5 вкладок — Смены (мои смены / явка / чек-листы / обмены), Задачи (задачи / заявки),
  Зал (стоп-лист / заказы / техкарты), Закуп, Зарплата.
- Владелец в дашборде: 8 сегментов — Обзор, График, Задачи, Смены, Зал, Закуп, Заявки, Зарплата.

**Что не так**
1. **Названия путаются.** «Смена» = и чек-лист, и вкладка; «Смены»/«Расписание» — одна вкладка
   под разными именами для сотрудника и менеджера; «Проверки» / «Аудиты» / «Аудит» — три имени
   одного раздела; «Отчёты» на вебе = «Заявки» на iOS; «Восьмёрка» без объяснения; «Зал» = «Floor»/«Hall».
2. **Явка на вебе спрятана:** Смены → сегмент «Явка» → «Я пришёл» + ожидание GPS. На iOS — сразу
   сверху. На iOS нет расстояния до точки, только тост «вне зоны».
3. **Менеджерское внутри «личного» People** (противоречит плану реструктуры 13.08): редактор графика,
   таблица опозданий всей команды, задачи «на роль», правка/удаление любых задач, CRUD техкарт.
4. **Сообщения-тупики:** «сначала отметьтесь», «сначала откройте смену», «нет смены» — без кнопки и
   без ответа «что мне сделать».
5. **Мёртвый код:** `AdHocAuditsView`, `fetchHasRelevantAudits` (веб), `AuditsTab`, ветка
   `checklistsSubTab="audits"` (iOS), `ChecklistHistorySheet`.
6. **Паритет:** на вебе нет календаря графика (только список), нет офлайн-очереди, заказы видны по
   разным правилам.

**Пакет B — разблокировать базовый день (S–M, главное для внедрения)**
- Гео: «включено, но адреса нет» = считать выключенным везде (веб + iOS + чек-лист) и показать
