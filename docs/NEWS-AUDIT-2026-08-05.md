## Починено в этой сессии

### 1. ВЫСОКО — iOS: ложный пуш о несуществующем посте
`NewsView.swift:109` — `try? await ...insert(values).run()` без проверки. При провале insert код
продолжал: слал пуш «новая новость» **всем сотрудникам** (`audience: ["all": true]`) и звал `load()`.
Итог: все получают уведомление о посте, которого нет в БД; автор не видит ошибки вообще
(`flash()` в модели был, но использовался только в `load()`).

**Фикс:** `do/catch` + `flash(t("nw.saveFailed"))` + ранний `return` до пуша. Аналогично `delete()` —
`flash(t("nw.deleteFailed"))`. Прецедент: `BookingsView.swift:187-192`.

### 2. СРЕДНЕ — веб: молчаливая потеря поста
`page.tsx:57-78` — `publish()` проверял `error` только на подстроку `/priority/` (фолбэк на
неприменённую миграцию). Любая другая ошибка (сеть, RLS, 403) игнорировалась: форма очищалась,
как будто пост создан. `removePost()` — вообще без проверки ошибки.

**Фикс:** проверка `error` в обеих функциях, `alert(tr('dash.notSaved') + error.message)`,
форма НЕ очищается при провале (черновик сохраняется).

### 3. СРЕДНЕ — веб не слал пуш сотрудникам
iOS слал безусловно (`audience: {all}`), веб-дашборд — не слал вообще. Та же асимметрия, что
чинили в Bookings (`3acda93`, находка 4).

**Фикс:** `pushNotify({ type:'news', audience:{ all:true }, data:{ module:'news' } })` после
успешного insert. `NotifyAudience` в `lib/notifyClient.ts` расширен полем `all` (сервер его уже
поддерживал — `lib/notify.ts:31,70`).

### 4. МЕЛОЧЬ — гонка кэша iOS
`DB.run()` чистит кэш fire-and-forget (`DB.swift:14`), немедленный `load()` после мутации мог
прочитать ещё не инвалидированный кэш — свежий пост не появлялся сразу.

**Фикс:** insert через `.single(NewsPost.self)` + локальная вставка в `posts` (тот же паттерн, что
в `AnalyticsModel.addAdvance`, `AnalyticsView.swift:513-520`); delete — оптимистичное удаление из
массива с откатом при ошибке. Повторный `load()` убран с горячего пути.

## Открытые находки

### 5. ВЫСОКО (авторизация) — любой сотрудник может опубликовать пост «всем» и удалить чужой
`app/api/db/route.ts:68`:
```ts
news_posts: { read: [...все], write: ['manager','analytics','stash','people'] },
// комментарий: «публикацию гейтит UI на должностных лиц»
```
Гейт только в UI (`app.isOfficial` на iOS, owner-дашборд на вебе). Сотрудник с доступом к любому
модулю может дёрнуть `/api/db` напрямую: вставить пост и **удалить любой чужой пост**.
Дополнительно `/api/notify` (`route.ts:15-28`) не проверяет роль вызывающего — `audience:{all:true}`
доступна кому угодно, то есть массовая рассылка пуша всей команде от имени кого угодно.

Отличие от `bookings` (та же политика): там доступ всем — **осознанное** продуктовое решение
(любой официант заводит бронь). Для News последствие тяжелее: спам/имперсонация в масштабе всего
заведения + удаление объявлений руководства.

**Что нужно:** серверная проверка «должностное лицо» для `news_posts` write (и, отдельно, для
`audience.all` в `/api/notify`). Требует понятия «official» на стороне `resolveCaller`
(`lib/apiAuth.ts`) — сейчас там только `owner` + список `apps`.

### 6. ВЫСОКО — веб: сбой загрузки стирает ленту
`page.tsx:45-53`:
```ts
const { data } = await db.from('news_posts').select('*')...
setPosts((data || []) as Post[])
```
Ошибка игнорируется, `data === null` → лента обнуляется и показывается пустое состояние
«Новостей пока нет». iOS этот класс уже защищает (`NewsView.swift:77-97` — перезапись только при
успехе + тост `refreshFailed`). Веб — нет.

### 7. СРЕДНЕ — iOS: провал публикации теряет набранный текст
`NewsView.swift:352-357` — `NewsCompose` зовёт `onPublish(...)` и **сразу** `dismiss()`, не дожидаясь
результата. При ошибке сети тост показывается (после фикса №1), но шторка уже закрыта и весь
набранный текст потерян. Тот же класс, что чинили в People (`66a5f85` — «dismiss без проверки
успеха»). Веб после фикса №2 черновик сохраняет — асимметрия платформ.

### 8. СРЕДНЕ — iOS: удаление из меню «···» без подтверждения
Два пути удаления с разным поведением:
- свайп (`NewsView.swift:163-165`) → `confirmationDialog`;
- меню «···» в карточке (`NewsView.swift:166-168` → `NewsCard:267`) → удаляет **мгновенно**, без
  подтверждения.

Веб везде требует inline-подтверждения. Удаление необратимо (нет корзины/undo).

### 9. СРЕДНЕ — время поста на iOS показывается со сдвигом на таймзону
`NewsView.swift:295-305` — собственный парсер:
```swift
ISO8601DateFormatter().date(from: iso) ?? flexibleDate(iso)
// flexibleDate: dateFormat "yyyy-MM-dd'T'HH:mm:ss", prefix(19), БЕЗ timeZone
```
`ISO8601DateFormatter()` без `.withFractionalSeconds` спотыкается о микросекунды Postgres
(`2026-08-05T01:23:45.123456+00:00`) → срабатывает фолбэк, который отрезает зону и парсит UTC-время
как **локальное**. В Цюрихе (UTC+2) пост, опубликованный в 20:00, показывается как «18:00».

В репозитории уже есть общий корректный парсер `parseISO()` (`Theme.swift:5-25`), созданный ровно
против этого бага — News его не использует, а дублирует сломанную версию.

### 10. СРЕДНЕ — «закрепление» важных постов ломается на длинной ленте
Обе платформы: `limit(100)` + `order created_at desc`, приоритетная сортировка выполняется
**клиентом** после загрузки (`NewsView.swift:82-87`, `page.tsx:50`). Срочный пост, оказавшийся за
пределами 100 новейших, не поднимется наверх — он просто не загружен. Пагинации нет.

### 11. СРЕДНЕ — веб публикует посты без автора
`page.tsx:60` — `base = { restaurant_id, kind, title, body }`; `created_by`/`created_by_name` не
заполняются (iOS их шлёт, `NewsView.swift:106-107`). Карточка автора (`page.tsx:118`,
`NewsCard:281`) у веб-постов пустая — объявление выглядит анонимным.

### 12. СРЕДНЕ (i18n) — авто-часть пуша уходит на языке отправителя
Пуш News не использует `titleKey`/`bodyKey`, поэтому `lib/notify.ts:114,153` берут литерал
отправителя. Сам текст объявления перевести нельзя (пользовательский ввод) — но **префикс
приоритета** («Срочно · ») и подстановка типа при пустом заголовке («Информация») генерируются
кодом и уходят всем на языке публикующего. Итальянский сотрудник получает пуш с русским префиксом.
Ключи под это в `lib/notifyStrings.ts` отсутствуют.

### 13. НИЗКО — сотрудник на вебе не может прочитать ленту
News на вебе живёт только в owner-дашборде (`app/dashboard/(shell)/news`). Сотрудничьи веб-экраны
(`/people`, `/manager`, `/tobacco`, `/analytics`) ленты не имеют. Сотрудник без iOS получает пуш, но
открыть объявление может лишь как строку в колокольчике (`app/people/page.tsx:129`) — без типа,
приоритета и подсветки.

### 14. НИЗКО — пост нельзя отредактировать
Ни UI, ни колонки `updated_at` в схеме (`news-2026-06.sql`). Опечатка в объявлении лечится только
удалением и повторной публикацией — с повторным пушем всем.

### 15. НИЗКО — нет ограничения длины
Ни в схеме (`body text NOT NULL`), ни в UI. Гигантский пост уедет в APNs целиком.

### 16. НИЗКО — пуш «всем» бьёт по APNs последовательно, без лимита и дедупа
`lib/notify.ts:137-161` — цикл по получателям последовательный, `sendPush` (`lib/apns.ts:95-102`)
шлёт каждый токен отдельным await. Для `audience:{all:true}` это N×M HTTP/2-запросов подряд в
теле одного запроса к `/api/notify`. Ни батчинга, ни рейт-лимита, ни дедупа на роуте
(`app/api/notify/route.ts:15-39`). На команде в 40 человек публикация новости — 40+ последовательных
вызовов внутри одного serverless-запроса.

Дополнительно: `lib/apns.ts:55` строит payload без проверки длины (лимит APNs 4 КБ), а ошибки APNs
кроме `BadDeviceToken`/`DeviceTokenNotForTopic` (`apns.ts:96-101`) молча проглатываются — не
логируются, не ретраятся. Длинное объявление уйдёт «в никуда» без следа в логах.

### 17. НИЗКО (i18n) — расхождение ключей и словарей между платформами
- Разные имена ключей под одно и то же: iOS `nw.type` (`Localization.swift:849`) vs веб `nw.kind`
  (`lib/i18n.tsx:1236`); iOS `nw.titleField` (`:854`) vs веб `nw.title` (`lib/i18n.tsx:1241`).
  Правка формулировки в одном месте не доезжает во второе.
- В веб-словаре нет `nw.delete`, `nw.emptyHint`, `nw.emptyHintManager`, `nw.new`, `nw.post`,
  `nw.saveFailed`, `nw.deleteFailed`; в iOS нет `nw.sub`, `nw.deleteConfirm`. Пока экраны разные —
  не ломается, но при портировании фич выстрелит.
- Покрытие языков полное (8/8) в обоих словарях.

Модуль News входит в `ALL_MODULES` (`lib/plans.ts:5,8`), в дашборде гейтится тарифом
(`app/dashboard/(shell)/layout.tsx:25`) — Business/Pro, не Starter.

### 18. МЕЛОЧЬ (не баг)
- Веб-фолбэк «миграция priority не применена» по string-match текста ошибки (`page.tsx:64`) —
  хрупко, но мёртвый код: миграция применена в июне. iOS такого фолбэка не имеет вовсе.
- `NewsModel.rid` (`NewsView.swift:61`) не используется — скоуп форсит шлюз.
- Тинт свайп-действия удаления — `BrandKit.menu` (`NewsView.swift:164`), а не акцент News/красный.
- Тип поста `stop` («стоп-лист») смыслово дублирует настоящий стоп-лист в People/Menu
  (`menu_items.is_available`) — продуктовое пересечение, не дефект.
