# Launcher tile interaction implementation plan

Goal/spec: user asks to fix moving/resizing home tiles without overlaps or stuck gestures,
verify in native simulator, publish nothing. Preserve branding, available modules and S/M/L.

Evidence: reproduced in simulator: moving Manager a short distance inside its own full-width
row sends it to the end. insertionIndex includes the moving-only row, then an empty visible
row defaults to order.count. Reorder then queries frames/rows that are changing under the
finger. Nested row ForEach changes tile identity across rows; resize/reorder have competing
recognizers, and cancelled gestures reset only after leaving edit mode.

Architecture: measured flat SwiftUI Layout keeps tile identity and a leading-aligned
three-column grid. A pure drag session snapshots order/frames, previews a stable insertion
without mutating saved order, and commits once on release. One gesture per tile classifies
move vs resize at touch start; named coordinates, GestureState cancellation, edit/background/
width/staff/permissions changes clear transient state. Resize preview never stretches across
neighbors; tap handle offers exact S/M/L. Accessibility actions move earlier/later and resize.
Normalize saved layouts to unique authorized modules while preserving order/sizes and appending
new modules. No network/schema/financial changes and no new dependencies.

Acceptance: short move within own tile stays put; drag across rows/both directions/endpoints
works; repeated positions do not oscillate; resize changes size only; all final frames stay
within width and disjoint, including variable heights; cancel preserves committed order;
release persists once; editing never opens a module; later tap opens normally; stale gesture
cannot lock scroll after edit/cancellation/background. Per-user persistence survives relaunch,
permission changes remove inaccessible IDs, duplicate saved IDs cannot create overlapping views.
