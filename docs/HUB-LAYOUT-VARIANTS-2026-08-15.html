Пять способов пересобрать хаб

Сейчас после входа — сетка 2×2, все плитки равного веса: иконка, заголовок, подпись (MainView.swift, LauncherView). Ниже — пять самостоятельных направлений: от лёгкой перекомпоновки веса до смены самой идеи экрана — из навигационного меню в живой дашборд. Цвета и иконки взяты из Theme.swift, контент — реальные модули (Manager, Analytics, Stash, People, Bookings, News).

Manager получает полноширинную плитку с живым статусом смены прямо на хабе — не нужно заходить, чтобы понять, открыта ли касса. Analytics и Stash — на второй по значимости уровень, с одной ключевой цифрой каждая. People/Bookings/News — компактный ряд для точечных заходов.

  • Иерархия считывается за долю секунды — не все шесть модулей соревнуются за внимание
  • Заготовка под будущее: новый модуль просто занимает своё место в третьем ряду
  • Мини-статы (12%, «2 на исходе») дают повод открыть приложение не только для навигации

Риск. Вес плитки — решение продукта, не пользователя: если у ресторана Analytics важнее Manager, сетку придётся либо адаптировать по роли, либо смириться с неидеальным умолчанием.

Ближе всего к нативному iOS-языку — одна колонка, построчно, точно как экран настроек. Правый край строки — самое ценное место: короткий статус (пилюля, число, время) без захода в модуль.

  • Масштабируется без переверстки — седьмой модуль это ещё одна строка, не новая сетка
  • Группы «Операции» / «Команда» готовят почву под ролевые права: сотруднику можно скрыть всю группу «Операции»
  • Меньше визуального шума, чем цветные плитки — читается как рабочий инструмент, не витрина

Риск. Теряется часть бренд-энергии текущих цветных иконок — список менее «глянцевый», больше про скорость, чем про впечатление при первом входе.

Верх экрана — не навигация, а ответ. Карточка кассы с суммой и мини-графиком закрывает самый частый вопрос без единого тапа. Остальные пять модулей уходят в горизонтальный док — доступны, но не спорят за внимание с главным числом.

  • Первый экран отвечает на вопрос, а не просто предлагает выбор — экономит один переход почти всегда
  • Док легко переставить под роль: у бухгалтера первым в доке может стоять Analytics
  • Свайпаемый ряд не ограничен шестью иконками — растёт вбок, не вниз

Риск. Работает, только если у роли есть один явный «главный» модуль. Для менеджера без доступа к кассе герою нечем быть — нужен второй вариант героя или откат к плоскому доку.

Иконки — просто линии белого цвета, без цветной подложки. Бренд-цвет модуля сжимается до точки слева — метка, не украшение. Число справа появляется только там, где есть что показать (склад на исходе, непрочитанные новости).

  • Меньше всего конкурирует с данными внутри модулей — хаб не «кричит» громче, чем экраны за ним
  • Близко к направлению iOS 18 (Shortcuts, Journal) — тонкие линии, точка вместо чипа
  • Число вместо статус-пилюли компактнее — влезает больше строк без скролла

Риск. Шесть ярких плиток сейчас — часть первого впечатления при входе; монохром спокойнее, но менее «вау» в момент онбординга нового пользователя.

Плитка перестаёт быть просто ярлыком и показывает главную цифру модуля: касса, дельта выручки, дефицит склада, кто на смене, ближайшая бронь, непрочитанные новости. Данные для всего этого уже считаются — тот же снэпшот, что питает виджет на домашнем экране (SnapshotWriter).

  • Единственный вариант, где хаб полезен даже без единого тапа — как утренняя сводка
  • Переиспользует готовую инфраструктуру расчётов, а не только UI-слой
  • Настраивается по роли естественно: сотруднику можно скрыть цифру кассы, оставив только статус

Риск. Больше всего работы на бэкенде экрана — шесть живых чисел вместо одной загрузки списка; нужна и оффлайн/skeleton-раскладка на время подгрузки данных.
