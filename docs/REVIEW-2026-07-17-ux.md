## А. Баги (P1)

- [x] **A1. Разовые/повторяющиеся аудиты (веб): отметка попадает в СТАРЫЙ прогон.**
  `app/people/page.tsx` AdHocAuditsView: `completions` грузятся БЕЗ фильтра по дате (`select('*')`),
  `setItem` ищет `completions.find(c => c.checklist_id === audit.id)` — для повторяющегося аудита
  найдётся вчерашний/произвольный прогон, сегодняшний тоггл перезапишет его. iOS фильтрует по
  `todayKey` — веб привести к тому же: грузить `eq('date', today)` (или последний прогон по дате)
  и искать по `(checklist_id, date)`.
- [x] **A2. Статистика аудитов считает «нарушениями» незаполненные прогоны.**
  AuditStatsView: каждый неотмеченный пункт любого completion (включая `status='pending'` —
  только что заведённые кроном/менеджером и ещё не открытые) идёт в «Топ нарушений» и роняет
  «% выполнения». Пустой pending-прогон = 100% нарушений. Считать только по завершённым
  (`status='done'`) или хотя бы `in_progress`+`done`; pending показывать отдельно как «не пройдено».
- [x] **A3. Веб-«Разовые»: нет редактирования/удаления шаблона аудита.** iOS даёт pencil/trash,
  веб — только создание. Ошибся в пункте — шаблон навсегда + каждый «запуск» создаёт НОВЫЙ шаблон
  (плодятся дубли в списке). Добавить edit/delete + повторный запуск существующего шаблона
  (как iOS `startAudit`), а не создание нового.
- [x] **A4. Дашборд-уведомления не показывают журнал `notifications`.**
  `dashboard/notifications/page.tsx` — только заказы QR-меню + low-stock + past_due. Явка,
  аудиты, кассы, нарушения, напоминания — владелец на вебе их не видит вообще (видит только
  пуш на телефоне). Добавить ленту из `notifications` (то же перерендеривание по
  `title_key`/`body_key`, образец — колокольчик в people/page.tsx:907).
- [x] **A5. Настройки напоминаний обещают то, чего cron не делает.**
  Settings → «Напоминание о смене»: режимы «за N часов»/«в фиксированное время» сохраняются,
  но cron (Vercel Hobby, 1 запуск/день) их игнорирует — шлёт всегда накануне. UI вводит в
  заблуждение. Либо скрыть режимы до апгрейда на Pro, либо подпись «работает после апгрейда»
  (комментарий в коде это признаёт, UI — нет).

## Б. Аудиты: до уровня SafetyCulture/iAuditor (P2)

Что уже есть и работает как у конкурентов: шаблоны, разовые запуски, расписание
(daily/weekly/monthly), адресация (точка/цех/сотрудник), обязательное фото, гео-гейт,
нарушение → задача с фото и пушем, статистика 30 дней, рейтинг сотрудников, пресеты (санитария).

Чего не хватает до «инспекторского» класса (в порядке ценности):

- [ ] **Б1. Статусы пункта: ✓ / ✗ / N/A вместо бинарного «отмечен».** Сейчас «не отметил» =
  «нарушение» — нельзя отличить «не проверял» от «проверил, плохо». У всех шести конкурентов
  пункт имеет исход pass/fail/na. Схема: `items_state[i].result: 'pass'|'fail'|'na'` (done
  оставить для обратной совместимости). Это же чинит смысл статистики (А2).
- [ ] **Б2. Комментарий к пункту.** Фейл без пояснения бесполезен для разбора. Поле
  `items_state[i].note` + textarea в карточке (веб и iOS).
- [ ] **Б3. Отчёт по прогону (PDF/шеринг).** Прогон завершён → одна кнопка «Отчёт»: шапка
  (точка, дата, кто), пункты со статусами, фото, комментарии. Инфраструктура PDF уже есть
  (iOS PDFSnapshot/renderPDF, веб pdfTable) — переиспользовать.
- [ ] **Б4. История прогонов аудита.** Сейчас виден только сегодняшний прогон; вчерашние
  результаты недоступны ни менеджеру, ни владельцу. Экран «история»: список прогонов по датам
  со статусом и % — вход в отчёт Б3.
- [ ] **Б5. Дедлайн и ответственный у задачи-нарушения.** createViolationTask создаёт задачу
  без срока. У MaintainX/SafetyCulture corrective action имеет due date. Поле срока + просрочка
  краснеет в задачах.
- [ ] **Б6. Балльная оценка (скоринг).** % выполнения уже есть — добавить веса пунктов позже,
  только если попросят клиенты. Не приоритет.
