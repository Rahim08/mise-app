## Критические проблемы (CRITICAL)

### C1. Утечка секретов в `.env.local`
- **Файл:** `.env.local` (корень проекта)
- **Описание:** Содержит live-ключи Supabase anon/service-role, Resend API key в открытом виде. `.gitignore` имеет правило `.env*`, но файл уже закоммичен. Любой с доступом к репозиторию может эмулировать service-role.
- **Действие:** Ротировать все ключи, удалить файл из git-истории (BFG / git filter-branch), добавить pre-commit hook.

### C2. APNs-ключ (`.p8`) закоммичен в репозиторий
- **Файл:** `AuthKey_W6HCZSDZ6W.p8` (корень проекта)
- **Описание:** Приватный криптографический ключ Apple Push Notifications. `.gitignore` содержит `*.p8`, но файл добавлен ранее.
- **Действие:** Ротировать ключ в Apple Developer, удалить из git-истории.

### C3. Отсутствует `deviceId` в AuthGate и NativeOnboarding — сломана аутентификация
- **Файлы:** `components/AuthGate.tsx:223`, `components/NativeOnboarding.tsx:204`
- **Описание:** Оба компонента вызывают `/api/auth/pin/check` с `{ restaurantId, pin }`, но **не отправляют `deviceId`**. Серверный роут требует `deviceId` и возвращает 400. Следствие — PIN-аутентификация **полностью не работает** через эти компоненты. Сравните с `app/join/page.tsx:104`, который отправляет `deviceId` корректно.
- **Действие:** Добавить `deviceId` в оба компонента.

## Высокие проблемы (HIGH)

### H1. Open Redirect в OAuth callback
- **Файл:** `app/auth/callback/route.ts:8,30`
- **Описание:** Параметр `next` из URL используется напрямую в `NextResponse.redirect()` без валидации. Атакующий может перенаправить пользователя на `https://evil.com` после аутентификации.
- **Действие:** Валидировать, что `next` начинается с `/` и не содержит `//`.

### H2. Отсутствует `middleware.ts` — нет централизованной защиты маршрутов
- **Описание:** Auth проверяется в каждом API-роуте отдельно через `resolveCaller()`. Любой новый забытый роут будет публичным.
- **Действие:** Создать `middleware.ts` с централизованной проверкой авторизации.

### H3. `staffToken` использует service-role ключ как fallback
- **Файл:** `lib/staffToken.ts:22-28`
- **Описание:** Если `MISE_TOKEN_SECRET` не задан, HMAC-секретом становится Supabase service-role JWT (base64 JSON, не high-entropy). Утечка service-role = возможность фабрикации staff-cookie.
- **Действие:** Сделать `MISE_TOKEN_SECRET` обязательным, fallback на ошибку.

### H4. Stripe webhook: передаёт `restaurantId` вместо user UUID
- **Файл:** `app/api/stripe/webhook/route.ts:58`
- **Описание:** `getUserById(restaurantId)` — restaurant UUID вместо auth.users.id. Тихо фейлится (try/catch), email-квитанция никогда не отправляется.
- **Действие:** Исправить передачу UUID, добавить логирование.

### H5. TypeScript strict mode отключен
- **Файл:** `tsconfig.json:11,30-31`
- **Описание:** `strict: false`, `noImplicitAny: false`. В документации указано "TypeScript strict", но реальный конфиг лоялен. Это позволяет null-unsafe паттерны и неявные `any`.
- **Действие:** Включить `strict: true`, исправить ошибки компиляции.

### H6. Дублирование auth-логики в 3 местах
- **Файлы:** `AuthGate.tsx`, `NativeOnboarding.tsx`, `app/join/page.tsx`
- **Описание:** Три независимые реализации PIN-аутентификации. Баг с `deviceId` — следствие этого дублирования.
- **Действие:** Вынести в общий хук/контекст.

### H7. `Money.symbol` — data race в iOS
- **Файл:** `native/Mise/Mise/Theme.swift:26`
- **Описание:** `nonisolated(unsafe) static var symbol` читается из разных контекстов без синхронизации.
- **Действие:** Использовать `@MainActor` или actor.

### H8. `I18n.code` — data race в iOS
- **Файл:** `native/Mise/Mise/Localization.swift:132`
- **Описание:** Глобальная мутабельная переменная пишется из `@MainActor`, читается из nonisolated контекстов.
- **Действие:** Защитить `@MainActor` или actor.

### H9. Force unwrap в iOS — потенциальные краши
- **Файлы:**
  - `PeopleView.swift:53` — `calendarMonth` инициализация
  - `PeopleView.swift:388` — `loadAttendance`
  - `BookingsView.swift:773` — `BookingCalendar` ячейки
- **Описание:** `Calendar.current.date(from:)!` — если вернёт nil, приложение крашнется.
- **Действие:** Заменить на `?? Date()`.

## Средние проблемы (MEDIUM)

### M1. CSP разрешает `unsafe-eval`
- **Файл:** `next.config.ts:30`
- **Описание:** Ослабляет XSS-защиту.

### M2. Rate limiting на в-pamuлях ненадежен на Vercel
- **Файл:** `lib/rateLimit.ts`
- **Описание:** In-memory `Map` не сохраняется между serverless-вызовами. PIN check использует DB-based лимитер (правильно), но AI, menu events, menu orders — нет.

### M3. Гонка данных в PIN rate limiting (TOCTOU)
- **Файл:** `app/api/auth/pin/check/route.ts:60-65`
- **Описание:** Non-atomic read-then-write для подсчёта попыток. Параллельные запросы могут обойти лимит.
- **Действие:** Использовать атомарный UPDATE с RETURNING.

### M4. `/api/auth/welcome` без авторизации
- **Описание:** Можно спамить приветственные письма на любые email.
- **Действие:** Добавить аутентификацию или CAPTCHA.

### M5. Аналитика меню может быть раздута
- **Файл:** `app/api/menu/event/route.ts`
- **Описание:** Анонимный POST для любого ресторана по slug.

### M6. Unhandled TypeError в AI-роуте
- **Файл:** `app/api/ai/route.ts:125`
- **Описание:** `messages[messages.length - 1].text` без проверки наличия массива/элемента.

### M7. Нет индексов в БД
- `shift_expenses.shift_id` — нет b-tree индекса
- `hookah_sales.shift_id` — нет индекса
- `staff_tasks.created_by` — нет индекса (assigned_to есть)

### M8. `restaurants.owner_id` без индекса
- Минимум 5 кодовых путей ищут ресторан по owner UUID без индекса.

### M9. Удаление аккаунта не атомарное
- **Файл:** `app/api/account/delete/route.ts:50-61`
- **Описание:** 20+ последовательных DELETE без транзакции/отката.

### M10. `.env.example` неполный
- Отсутствуют: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `GROQ_API_KEY`, `CRON_SECRET`, `HEALTH_CHECK_SECRET`, `MISE_TOKEN_SECRET`, `TELEGRAM_*`, `APNS_*`, `MISE_EMAIL_FROM`, `NEXT_PUBLIC_POSTHOG_*`.

### M11. Нет общих типов между web и iOS
- Модели данных определены инлайн в каждой странице (TypeScript) и отдельно в Swift. Возможен drift.

### M12. Хардкоженные русские строки в push-уведомлениях iOS
- **Файл:** `native/Mise/Mise/ManagerView.swift:204`
- **Описание:** `"Касса открыта"`, `"Смена открыта"` — не локализованы.

### M13. NotificationSettingsView: гонка при быстром toggle
- **Файл:** `native/Mise/Mise/MainView.swift:371-388`
- **Описание:** Каждый toggle запускает async Task insert/update. Быстрые нажатия = дубли строк.
- **Действие:** Debounce save или serial queue.

### M14. StashModel.saveMovement: `try?` проглатывает ошибки
- **Файл:** `native/Mise/Mise/StashView.swift:338-356`
- **Описание:** Если insert прошёл, а update stock упал — движение записано, но stock не обновлён.
- **Действие:** Использовать транзакцию или abort on first failure.

### M15. BookingEditor: нет идемпотентности
- **Файл:** `native/Mise/Mise/BookingsView.swift:184-203`
- **Описание:** Двойной tap = двойное бронирование.

### M16. ACL-политики v2 миграции wide-open
- **Файл:** `people migration v2.sql:107-115`
- **Описание:** `USING (true) WITH CHECK (true)` на всех People-таблицах. Заменено в v3, но если v2 отработал без v3 — данные полностью доступны.
